# 实验室仓库使用规范

## 获取访问权限

- 从[组织首页](https://github.com/cumtb307)了解项目。需要访问私有项目时，通过[组织邮箱](mailto:Yang216099@163.com)说明 GitHub 用户名、项目和用途。
- 获取访问权限后，先读目标仓库的 README 和协作说明，按其中记录的运行环境、依赖工具、锁文件和命令启动项目。新增依赖时同步更新相应的依赖文件和锁文件。

## 提交改动

- 改动围绕一个明确目的展开。按项目约定从对应分支开展工作，并通过 Pull Request 提交需要评审的变更。
- 提交说明写清具体改动。Pull Request 说明修改原因、影响范围和实际验证结果，同时更新相关文档。
- 提交前运行受影响模块的检查或测试，记录命令和结果。报告问题时提供环境、复现步骤、预期与实际行为，以及可分享的最小示例。

## 记录实验

- 保存代码版本、依赖环境、配置、数据来源和版本。涉及随机实验时记录种子和评估口径。
- 报告结果时注明适用条件。使用合成数据或仿真场景时，在说明中标明数据和场景的性质。

## 处理资料与许可

- 将凭据、个人信息和内部数据保存在受控位置。公开示例和问题报告使用可公开的材料。
- 引用外部代码、数据或模型时，记录来源、版本、许可及本地修改。公开源码、数据和模型产物时，以实际发布内容中的授权说明为准。
